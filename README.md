# 公務人員考試歷屆試題複習系統（中國科技大學 管理學院）

純靜態網頁，掛在 GitHub Pages，學生開網址即用，免登入、免後端。

## 目前功能

| 需求 | 實作 |
|---|---|
| 學生透過網頁連線 | GitHub Pages 網址 |
| 亂數出題 | 隨機出題／依考點練習／錯題重練；可篩年度、題數；同一輪不重複 |
| 網頁輸入答案 | 選擇題點選選項；可選每題 72 或 45 秒倒數，時間到自動算未答 |
| 送出後評分並給完整答案建議 | 立即顯示對錯、得分、正確答案與詳解；支援考選部「更正答案」與「一律給分」 |
| 接續練習或停止 | 下一題／結束並檢視紀錄／繼續練習；關掉網頁後可「接續上次紀錄」 |
| 複習輔助 | 錯題本、各考點答對率、複製文字紀錄、列印或存成 PDF、備份與匯入紀錄 |

紀錄只存在學生自己的瀏覽器，不會傳到任何伺服器。

## 檔案

```
index.html        前端（HTML + CSS + JS，無外部套件）
core.js           出題、評分、統計邏輯（可用 Node 單獨測試）
data/bank.json    題庫（選擇題）
data/essays.json  申論題：題目、參考答案、評分細目
docs/             申論題參考答案的可讀版本（由 essays.json 產生）
tests/            test_core.js（選擇題與出題邏輯）、test_essay.js（申論題）
.nojekyll         讓 GitHub Pages 原樣提供檔案
```

## 部署到 GitHub Pages

1. 在 GitHub 建立倉庫（Pages 在免費方案只支援公開倉庫，題庫與詳解會是公開的）。
2. 把本資料夾的所有檔案放進倉庫根目錄（網頁介面：Add file → Upload files；或 `git push`）。
3. Settings → Pages → Source 選 Deploy from a branch，Branch 選 main、資料夾選 / (root)，按 Save。
4. 1 至 2 分鐘後網址為 `https://<帳號或組織>.github.io/<倉庫名>/`。

本機測試：在資料夾執行 `python3 -m http.server 8000`，開 http://localhost:8000。不要直接雙擊 index.html（瀏覽器會擋住讀取題庫檔）。

## 新增題目

在 `data/bank.json` 的 `questions` 陣列加入題目，格式如下。載入時系統會檢查格式，有誤會顯示錯誤訊息。

```json
{
  "id": "113-econ-1",
  "year_roc": 113,
  "exam": "公務人員普通考試",
  "categories": ["金融保險", "統計", "經建行政", "商業行政"],
  "subject": "經濟學概要",
  "question_no": 1,
  "type": "mcq",
  "points": 2,
  "question": "題目全文",
  "options": ["選項 A", "選項 B", "選項 C", "選項 D"],
  "answer": "A",
  "accept": null,
  "give_all": false,
  "correction_note": "",
  "explanation": "詳解",
  "area": "個體經濟",
  "tags": ["生產可能曲線"],
  "source": "考選部考畢試題查詢平臺"
}
```

- id 命名：普考 `113-econ-1`、初等 `113-elem-1`、高考三級 `113-g3fin-1`（經濟學與財政學概論）、`113-g3econ-1`（經濟學）、`115-g3mb-1`（經濟學與貨幣銀行學）、初等交通行政 `113-trans-1`（運輸學大意，114、115 年同理為 `114-trans-1`、`115-trans-1`）、初等統計 `113-stat-1`（統計學大意）、初等會計 `115-aelem-1`（會計學大意）、高考三級中級會計學 `115-g3inter-1`、高考三級會計學 `115-g3acct-1`、普考會計學概要 `115-acct-1`（113、114 年同理為 `113-aelem-1`、`113-g3inter-1`、`113-g3acct-1`、`113-acct-1`，及 `114-aelem-1`、`114-g3inter-1`、`114-g3acct-1`、`114-acct-1`）。其餘科目的代碼：初等財政學大意 `113-pfelem-1`、高考三級財政學 `113-g3pf-1`、初等稅務法規大意 `113-taxelem-1`、高考三級稅務法規 `113-g3tax-1`、普考稅務法規概要 `113-tax-1`、普考經濟學與財政學概要 `113-fin-1`、高考三級民法 `113-g3civ-1`、民法（包括民法總則、債編與物權編）`113-g3ftc-1`、高考三級行政法 `113-g3admin-1`、普考民法概要 `113-civ-1`、普考行政法概要 `113-adm-1`、初等交通行政大意 `113-tadm-1`（114、115 年同理）。新增科目時請取新的代碼，id 不可重複。
- 前端的「考試別、科目、年度、考點」選單都由題庫資料自動產生，新增科目或年度**不需要改程式**，只要把題目加進 `bank.json`。
- 新增後請同步更新 `tests/test_core.js`：`KEYS`（各份試卷的標準答案）、總題數（`bank.questions.length`）、各年度題數與試卷份數，再執行 `node tests/test_core.js`。測試會自動檢查每份試卷題號連續、滿分為 50 或 100 分、每題都有適用類科；但民法、行政法、財政學、稅務法規等科目目前沒有逐題對照答案卡的 `KEYS`，答案正確性只能靠人工對照考選部公布的答案。
- 考選部公告更正答案：改 `answer`，或在 `accept` 填多個可接受答案（如 `["A","C"]`），並在 `correction_note` 註明。
- 公告一律給分：`give_all` 設為 `true`。
- `question` 與 `explanation` 允許少量 HTML（`<sub>`、`<sup>`、`<br>`、`<table>`），其餘欄位一律當純文字。題庫只能由維護者修改，不要放入來路不明的內容。

## 申論題練習與評分

流程：設定畫面選到有申論題的科目（目前為高考三級「經濟學」）→ 出現「申論題練習」面板 → 選題作答 → 每小題各自送出評分。

評分分兩步，**第二步由學生確認**：

1. **系統初判**：把學生的答案做文字正規化（全形轉半形、`²` 轉 `2`、去空白與括號、統一減號），再比對每個「評分細目」的關鍵字／公式寫法（正規表示式）。`d²/(2b)`、`d^2 / 2b`、`\frac{d^2}{2b}` 會被視為同一種寫法。
2. **學生確認**：初判結果預填在各細目的下拉選單（0、0.5、1…至該細目配分），學生對照參考答案自行調整，總分即時更新。

重要限制：系統只認關鍵字與寫法，**看不懂推導是否正確**。學生用不同寫法會漏判，只提到名詞但推導錯誤也可能誤判，所以最後分數一定由學生確認，且分數僅供自我檢視，不等於閱卷結果。若需要語意層級的批改，必須人工或另接後端／AI 服務（靜態網頁無法保護金鑰，本專案不做）。

草稿（作答文字、評分）自動存在瀏覽器，關掉網頁再開可接續；按「儲存本題成績並結束」才會寫入成績紀錄。備份檔（版本 2）會一併包含申論題草稿與成績，舊版備份仍可匯入。

### 新增申論題

在 `data/essays.json` 的 `essays` 陣列加入題目。載入時會檢查格式，有誤時申論題面板不會出現，並在瀏覽器主控台印出原因。

```json
{
  "id": "115-g3econ-E1",
  "year_roc": 115, "exam": "公務人員高等考試三級考試", "categories": ["統計", "經建行政"],
  "subject": "經濟學", "question_no": 1, "points": 25, "area": "個體經濟",
  "tags": ["外部性"],
  "question": "題目共同敘述（允許少量 HTML）",
  "parts": [
    {
      "id": "1", "label": "（一）", "points": 5,
      "question": "小題題目",
      "model_answer": "參考答案（允許 <br>、<b>、<sub>、<sup>）",
      "rubric": [
        { "id": "r1", "label": "得分點說明", "points": 1.5,
          "patterns": ["a-c-d/b", "社會邊際成本.{0,12}c\\+d"], "min": 1, "hint": "選填，顯示在細目下方" }
      ],
      "pitfalls": "常見錯誤（選填）"
    }
  ],
  "source": "出處"
}
```

- 各小題 `points` 加總必須等於 `points`；各細目 `points` 加總必須等於該小題 `points`。
- `patterns` 是**對正規化後文字**比對的 JavaScript 正規表示式字串（JSON 內反斜線要寫成 `\\`）。因為括號、空白、`*`、`^`、`_` 與句點都已被去掉，`Q*=(a-c-d)/b` 會變成 `q=a-c-d/b`。字母一律小寫。
- `min`：至少要符合幾條 pattern 才給滿分；符合但不足時按比例給分（進位到 0.5）。概念型細目建議 `min: 2`，避免只提到一個名詞就拿滿分。
- 寫完請跑 `node tests/test_essay.js`：它會檢查格式、確認「參考答案本身必須拿滿分」、空白答案必須 0 分，並用數值方法驗算第一題的公式。新增題目時請照樣加上自己的驗算。
